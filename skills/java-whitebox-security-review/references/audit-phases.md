# Audit Phases

## Phase 0：项目度量

目标：

- 统计源码规模
- 识别模块数量
- 判断审计深度和覆盖要求

## Phase 1：项目侦察

目标：

- 识别构建工具
- 识别框架与安全组件
- 梳理主要入口和配置文件

## Phase 2：双轨审计

目标：

- 对注入、文件、SSRF、反序列化等执行 sink-driven
- 对认证、授权、业务边界执行 control-driven

## Phase 2.5：覆盖率检查

目标：

- 判断关键入口是否被覆盖
- 回补遗漏的 T1/T2 文件

## Phase 3：证据校验

目标：

- 验证调用链完整性
- 验证安全控制是否真实缺失
- 给每个发现项分配置信度

## Phase 4：规则沉淀

可选：

- 将高价值模式沉淀为后续规则或检查清单

## Phase 5：报告输出

目标：

- 输出统一结构的审计报告
- 汇总高风险与优先修复建议
